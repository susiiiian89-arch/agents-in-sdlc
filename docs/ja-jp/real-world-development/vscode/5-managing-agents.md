GitHub Copilot をエージェントモードにすると、コードベースを調査し、変更を提案し、ファイルを編集し、コマンドを実行します。作業は自分のマシンでリアルタイムに行われるため、VS Code の Copilot Chat では各ツール呼び出しやファイル編集の状況を確認できます。差分をその場でレビューし、個々の変更を採用または却下できます。また、エディターを離れずに追加のプロンプトを送信し、会話を調整または拡張できます。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッションの途中でエージェントに指示し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから新たな依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替え機能も追加したいとのことです。最初から新しい会話を始めるのではなく、現在のセッションを継続して作業を追加します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順（調査するファイル、実行するコマンド、提案する編集）が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業してもらいます。
4. チャット上部の **Files changed** を開き、このセッションでエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツール呼び出しの許可を求められることがあります（たとえば、ターミナルコマンドの実行）。エージェントは一時停止して **Allow** を表示します。内容を確認し、実行してもよいコマンドのみ承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## エージェントにライトモードを追加するよう依頼する

ハイコントラストモードが実装されたので、同じ会話にライトモードの切り替え機能を追加します。同じチャットセッションを続けるため、エージェントは前の作業（変更したコンポーネント、スタイルの方針、local storage を使ったパターン）を引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    よくできました。次に、ハイコントラストの切り替えに加えて、ライトモードの切り替えも追加してください。ライトモードも同じパターンに従い、local storage に設定を保存して、同じ UI 領域から操作できるようにしてください。ハイコントラストモードとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントは前の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストの場合と同様に、新しい編集ごとに内容を確認します。差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが期待と異なる方向に進んだ場合（たとえば、好みと異なる方法で切り替え UI をリファクタリングしようとした場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送信して方向を修正します。

> [!TIP]
> 作業中のセッションを調整する方が、最初からやり直すよりも短時間で済みます。追加のプロンプトを使って変更（「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」）、方向修正（「3つ目の切り替え項目は追加せず、既存の設定パネルにライトモードを追加する」）、範囲の拡張（「両方の切り替え機能にキーボードショートカットも追加する」）を依頼できます。

## 作業内容を確認する

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code の **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による保存など、カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使い、作業中のセッションを監視して調整しました。ファイル編集を確認し、採用または却下して、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または却下しました。
- 追加プロンプトで作業中のセッションを調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業を pull request として公開し、このラボを通じてローカルのカスタムエージェントが行った変更をレビューします。
