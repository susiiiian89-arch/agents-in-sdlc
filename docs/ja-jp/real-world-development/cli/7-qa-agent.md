`quality-checks` スキルを使って自動チェックを実行し、Playwright MCP でブラウザー上のフィルタリングを確認しました。次は、明確な QA プロセスを備えたカスタムエージェントに、これらの機能をまとめます。

このレッスンでは、次の操作を行います。

- カスタムエージェントが指示、スキル、MCP ツールとどのように連携するかを確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリングの issue に照らして結果を確認します。

## シナリオ

Tailspin Toys では、pull request（PR）を作成する前に、要件、コード品質、自動チェック、テストカバレッジ、ブラウザー上の動作を一貫した方法で確認したいと考えています。カスタムエージェントを使うと、QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する Copilot の専門的な役割です。プロファイルには、エージェントの目的、指示、利用できるツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を説明します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、これらの機能を要件の評価や結果の報告にどう使うかを Copilot に伝えます。ほかの機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、再利用可能な QA プロファイルを作成するよう Copilot に依頼します。プロファイルでは、QA で実行するチェックと、その作業の制約を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   `.github/agents/qa.agent.md` に QA という名前のカスタムエージェントを作成してください。issue と合意済みの要件に照らして機能を確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、テストカバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示しながら pass、fail、blocked のいずれかで報告させてください。実装コードを変更する前には必ず確認を求め、変更をコミットしたり pull request を開いたりしてはいけません。

   今はレビューできるようにプロファイルを作成するだけにしてください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、意図した QA の手順と制約がプロファイルに反映されていることを確認します。これにより、検証だけを依頼したのに不完全な指示や広すぎる権限で機能を変更してしまう事態を防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. フロントマターを確認します。`description` は必須です。`name` は省略できますが、設定するとエージェント名が明確になります。
3. プロファイルの指示を読み、QA が要件を確認し、リポジトリの指示に従い、`quality-checks` スキルを実行して、Playwright MCP を利用することを確認します。
4. QA が根拠を示して報告すること、実装コードを変更する前に確認を求めること、変更のコミットや pull request の作成を行わないことを確認します。
5. これらの役割や制約が不足している場合は、既定のエージェントに修正を依頼してから続行します。

## issue を基に QA を実行する

Copilot CLI は会話開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成したら同じフィルタリングの会話を再開し、QA を選択します。そうすると、issue と計画の判断を引き継いで利用できます。

1. 次のプロンプトを使ってエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、利用可能なエージェントの一覧にまだ表示されない場合があります。上記のコマンドを実行すれば有効になります。

2. 次のプロンプトで、QA エージェントに機能をレビューするよう依頼します。

   ```plaintext
   issue と計画で決めた内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか？
   ```

3. QA エージェントが作業を開始します。
4. 完了したら、レポートを確認します。
