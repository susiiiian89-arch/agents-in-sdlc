アプリの小さな更新でも、通常は複数のファイルを変更し、テストなどの操作を実行する必要があります。開発者は通常、必要なファイルを探し、変更を加え、テストを実行し、問題をデバッグし、更新し忘れたファイルを見つけて再び変更します。この作業は次々と続きます。

ここで役立つのが Copilot エージェントモードです。

Copilot エージェントモードは、IDE 内でより自律的に作業します。開発者のように既存のプロジェクト構成を調査し、必要な変更を行い、テストなどのタスクを実行して、見つかった問題を自動的に修正します。エージェントモードを使ってサイトに新機能を追加する方法を確認しましょう。

> [!NOTE]
> 名前は似ていますが、エージェントモードと cloud agent は異なる用途向けに作られています。エージェントモードは IDE 内でタスクを実行するため、すばやく結果を確認し、やり取りしながら進められます。cloud agent はチームの一員のように非同期で作業し、issue や pull request を介して連携します。

この演習では、次の操作を学びます。

- Copilot エージェントモードでプロジェクトを調査し、関連ファイルを特定して、複数のファイルにまたがる変更を行う方法。
- GitHub Copilot エージェントモードで UI とデータレイヤーに新機能を実装する方法。
- Copilot エージェントモードが生成した変更とテストを、コードベースにマージする前にレビューする方法。

## シナリオ

ゲームの一覧が増えてきたため、カテゴリやパブリッシャーで絞り込めるようにします。前の演習でパブリッシャーヘルパーを追加しました。今回は Copilot エージェントモードを使って、残りのデータレイヤー、UI、テストを実装します。

## Tailspin Toys の Web サイトを実行する

変更を加える前に、Tailspin Toys の Web サイトを確認し、現在の機能を把握しましょう。

このサイトは開発者向けテーマのボードゲーム用クラウドファンディングプラットフォームです。ゲームを一覧表示し、その詳細を確認できます。単一の Astro アプリで、ビルド時にページを静的 HTML として生成します。ページは frontmatter から Drizzle ORM を使ってローカルの SQLite データベースを直接参照します。別のバックエンド API やクライアント側の UI フレームワークはありません。再利用可能なデータアクセスヘルパーは `src/lib/` にあり、必要なインタラクティブ機能には標準の DOM API を使った小規模な Astro `<script>` を使用します。

### Web サイトを起動する

Web サイトを簡単に実行できるよう、単一の Astro 開発サーバーを起動する `npm run dev` タスクが用意されています。GitHub Codespace では次の手順で実行できます。

1. Codespace に戻ります。前の演習から `main` に戻っているはずです。
2. <kbd>Control</kbd>+<kbd>`</kbd>（Mac）または <kbd>Ctrl</kbd>+<kbd>`</kbd>（Windows/Linux）を押し、Codespace で新しいターミナルを開きます。
3. フィルタリング作業用のブランチを作成して切り替えます。

   ```bash
   git checkout main
   git pull
   git checkout -b filtering-vscode
   ```

4. 次のコマンドを実行して Web サイトを起動します。

   ```bash
   npm run dev
   ```

   Astro 開発サーバーの準備ができると、次のような URL を示すメッセージが表示されます。

   ```bash
   🚀 Tailspin Toys is ready!
      Astro server: http://localhost:4321
      Press Ctrl-C to stop.
   ```

> [!NOTE]
> `http://localhost:4321` を開くブラウザーウィンドウの表示を促すダイアログが開いた場合は、**x** を選択して閉じます。

5. <kbd>Command</kbd>（Mac）または <kbd>Ctrl</kbd>（Windows/Linux）を押しながら、ターミナルに表示された Astro サーバーのアドレス `http://localhost:4321` を選択し、Web サイトを開きます。

> [!NOTE]
> Codespace のターミナルで localhost の URL を選択すると、自動的に `https://<your-codespace-name>-4321.app.github.dev/` に転送されます。これは Codespace のサーバーをホストするプライベートトンネルです。

### Web サイトを確認する

サイトを起動したら、機能を確認します。主な機能は次のとおりです。

- **ホームページ**: ボードゲームのタイトル、画像、説明を一覧表示します。
- **ゲーム詳細ページ**: ゲームを選択すると、タイトル、説明、パブリッシャー、カテゴリなどの詳細が表示されます。

## Copilot でバックログを確認する

> [!TIP]
> **Copilot Chat を開く**
>
> 以下の演習を始める前に Codespace に戻り、Copilot Chat パネルを開いて **New Chat** を選択し、新しい会話を始めます。モードとモデルの選択は演習によって異なります。必要な場合は、各手順で説明します。

Web サイトの初期実装は動作しますが、さらに機能を追加したいと考えています。まずバックログを確認しましょう。テンプレートからプロジェクトをセットアップした際に issue が自動的に作成されています。GitHub Copilot に一覧を表示してもらいます。

1. Chat ビューのエージェント選択メニューから **Agent** を選択します。**Agent** はファイルにまたがる変更を自律的に計画・実装し、ターミナルコマンドやツールを実行します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

2. 利用可能なモデル一覧から **Claude Sonnet 4.5** を選択します。

> [!CAUTION]
> このワークショップの作成者が特定のモデルを推奨しているわけではありません。ワークショップの作成時に Claude Sonnet 4.5 を使用したため、手順にも記載しています。提案されるコードに一貫性を持たせ、使いやすくすることを意図しています。ただし、LLM の動作は確率的なため、ここに記載されたものと異なる提案が表示される場合があります。これは正常な動作です。

> [!NOTE]
> 確率的な性質により、Copilot が別の MCP コマンドを使う場合がありますが、タスク自体は完了できるはずです。

3. 次のプロンプトを Copilot に送信して、issue のバックログを確認します。

   ```plaintext
   GitHub リポジトリのバックログ項目を表示してください。ユーザーに最も役立つ項目を基準に、優先順位付けを手伝ってください。
   ```

4. **Continue** を選択して、すべての issue を一覧表示するコマンドを実行します。
5. 生成された issue の一覧を確認します。

Copilot は、ユーザーに最も役立つと思われる項目を優先順位付けしてくれます。

## 指示ファイルを確認する

エージェントにコードを生成させる前に、作業のコンテキストを Copilot に伝える指示ファイルを確認しましょう。Web サイトに機能を追加する方法を説明する [ユーザーインターフェイス（UI）](https://github.com/github-samples/tailspin-toys/blob/main/.github/instructions/ui.instructions.md) ファイルを使います。

1. Codespace で `.github/instructions/ui.instructions.md` に移動します。
2. 機能追加に関する全体的なガイダンスを確認します。次の内容が含まれています。
   - アーキテクチャの概要。
   - コンポーネントの設計、テスト可能性、アクセシビリティの原則。
   - Astro、Tailwind CSS、Drizzle など、さまざまなファイル種別に関する指示へのリンク。

> [!TIP]
> 指示ファイルから、ほかの指示ファイルやプロジェクト内のファイルを参照できます。パスは指示ファイルの場所を基準とします。これにより、指示を再利用可能な小さなファイルに分割し、参考例を指定できます。

## フィルタリング機能を実装する

フィルタリングを完成させるには、少なくとも次の3種類の更新が必要です。

- データレイヤー（`src/lib/`）の残りのフィルタリングロジックを追加または改善します。
- フィルタリングの動作を確認するテストを追加または更新します。
- ゲーム一覧ページにフィルタリング UI を追加します。

さらに、コードベースにマージする前にテストを実行し、すべて成功することを確認する必要があります。Copilot エージェントモードを使って作業できます。機能を追加しましょう。

1. Copilot との現在の会話を続けるか、**New Chat** を選択して新しい会話を開始します。
2. **Add Context**、**Instructions**、**ui** の順に選択し、指示ファイルを追加します。

   ![UI 指示ファイルを選択する例](../../../_images/ex3-select-instructions-file.png)

3. Chat ビューのエージェント選択メニューで **Agent** が選択されていることを確認します。

   ![Chat ビューのエージェント選択メニュー](../../../_images/shared-chat-mode-selector.png)

4. モデルに **Claude Sonnet 4.5** が選択されていることを確認します。
5. バックログの関連 issue に基づいて機能を実装するよう、次のプロンプトで Copilot に依頼します。

   ```plaintext
   バックログ内の関連する GitHub issue の要件に基づいて、パブリッシャーとカテゴリでフィルタリングできるようサイトを更新してください。前の演習で追加したパブリッシャーヘルパーを維持し、必要に応じて改善しながら、残りのデータレイヤー、UI、テストを完成させてください。完了前にすべてのテストが成功することを確認してください。サーバーはすでに実行中なので、起動する必要はありません。
   ```

6. Copilot がプロジェクトを調査し、機能に関係するファイルを特定する様子を確認します。データレイヤーのヘルパー、UI、テストが見つかり、ファイルの変更とテストの実行が始まります。

   ![Copilot がプロジェクトを調査する画面](../../../_images/ex3-agent-mode-explores.png)

> [!NOTE]
> Copilot はプロジェクトを調査し、ファイルを変更して、テストを実行します。タスクやコードベースの複雑さによっては数分かかることがあります。作業中、コードエディターに **Keep** と **Undo** が表示される場合があります。Copilot の作業中に選択する必要はありません。完了すると、すべての変更に対して **Keep** または **Undo** が表示されます。

7. Copilot に求められたら **Continue** を選択してテストを実行します。

   ![Copilot Chat のペインでテスト実行の確認を求めるダイアログ](../../../_images/ex3-agent-mode-run-tests.png)

8. 作業中に何度か停止したり、テストが失敗したりする場合があります。問題ありません。Copilot はコード生成とテストの実行を繰り返し、エラーがないと判断するまで作業を続けます。

   ![Copilot エージェントモードの会話が完了した画面](../../../_images/ex3-agent-mode-proposed-changes.png)

9. 生成されたコードに問題がないか確認します。

> [!CAUTION]
> Copilot などの AI ツールが生成したコードは、必ずレビューしてください。

10. Web サイトが開いているブラウザーに戻り、新機能を試します。
11. 動作とコードを確認したら、Copilot Chat ウィンドウで **Keep** を選択します。

- Copilot エージェントモードでプロジェクトを調査し、関連ファイルを特定して、複数のファイルにまたがる変更を行う方法。

### ボーナス演習 - ページネーションを実装する

ゲームの一覧が増えると、ページネーションが必要になります。この演習で学んだことを使い、Copilot にページネーションを実装してもらいましょう。次の点を検討してください。

- 既存の指示ファイルを使うなど、ベストプラクティスに従います。
- ユーザーがページサイズを選べるようにするか、固定値にするかなど、ページネーションの方法を決めます。
- 希望どおりの実装に必要なガイダンスを、プロンプトに含めます。
- 必要に応じて Copilot に変更を依頼し、コンテキストを補いながら反復します。これは Copilot を使う通常のワークフローです。
